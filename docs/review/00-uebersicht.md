# Review 00: Module nach Risiko

Stand: 10.10.2026, Branch `main` (Commit `a08c5f7`). Diese Übersicht ist der Ausgangspunkt für ein
Review. Sie beschreibt jedes Modul in einem Satz und sortiert nach Risiko. Ganz oben steht, was
Anmeldung, Datenzugriff und Nutzereingaben betrifft. Am Code wurde nichts geändert.

**So ist sortiert:** Ein Modul steht weiter oben, wenn ein Fehler darin

1. ohne Anmeldung erreichbar ist,
2. Daten eines anderen Mandanten oder einer anderen Rolle freigeben könnte,
3. ungeprüfte Eingaben in Dateien, SQL oder HTML weiterreicht oder
4. Nachweise verfälscht, die ein Auditor prüft.

Die Spalte „Worauf achten“ nennt den Grund für den Platz. Sie ist kein Befund. Ob dort ein Fehler
steckt, klärt erst das Review.

## Vorschlag für die Reihenfolge des Reviews

1. Anmeldung und Token (Nr. 1, 7), zusammen mit Mandantentrennung und Rechten (Nr. 2 bis 5).
2. Datei-Upload, Speicher und Exporte (Nr. 8 bis 10), denn dort verlassen Daten das System oder kommen von außen herein.
3. Vier-Augen-Regeln quer durch die Fachmodule (Nr. 15 bis 24): Lässt sich ein Schritt über einen anderen Endpunkt umgehen?
4. Fristenrechnung (Nr. 13, 27), weil gesetzliche Meldefristen daran hängen.
